S — Single Responsibility Principle (SRP)
      A class should have only one reason to change.
            Group all the related functionality into seperate responsible classes 
      
O — Open/Closed Principle (OCP)
      Software entities should be open for extension, closed for modification.
            It should be be easirer to add any new class to exixting code.
            Make use of interface and abstract classes for achiving the goal.
            
L — Liskov Substitution Principle (LSP)
      Subclasses must be usable wherever their base class is expected.
            where ever a child class is used it should not throw execption in the overrided fucntion if they are not used.    
      
I — Interface Segregation Principle (ISP)
      Clients should not be forced to depend on methods they do not use.
            create a separate interface for all the related functionallty. 
      
       
D — Dependency Inversion Principle (DIP)
      High-level modules should not depend on low-level modules.
      Both should depend on abstractions.
            motly ise interface and abstraction for decoupling
